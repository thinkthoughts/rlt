# RLT-002 · T7 — Registered chemical notation: implementation report

**Scope.** This report covers the T7 architecture as approved ("RLT-002 T7 — Architecture Approved for Implementation", decisions D1–D9 with clarifications), built on `rlt-002` in the approved order. `kernel/`, `spec/`, the registered axiom set and the proof rules are byte-identical to `origin/main`.

**Result.**
- `CHEM-MOLFORMULA` reads exactly `CO₂` and `O₂` through a closed, pinned species table. `COO`, `CO2` and `O2` stay uninterpreted.
- `points/co2-and-o2.yaml` binds math5's example to seven reading points: two molecules and five atoms.
- Two composition records are checked against the registered entries.
- Three counts are checked by the kernel.
- Every physical correspondence stays `unestablished`.

## 1. What was built, in order

| Step | Change | Files |
|---|---|---|
| 1 Convention pins | Each convention has three parts: top-level `id`, `authority`, `sources` and `origin`; an `executable:` block; and an `explanation:` block. `PINNED_CONVENTIONS` holds two SHA-256 digests per convention over a canonical form of the parsed YAML (sorted keys, length-prefixed strings). The interpretation digest covers everything outside `explanation:`; the explanation digest covers the prose. Unknown fields are refused, and so are `symbols` outside the symbol elaborator. Every command except `validate` reads conventions through `pinned_conventions`; `validate` reports each mismatch as a problem | `conventions/*.yaml`, `syntax/src/records.rs` (`load_convention`, `canonical`), `cli/src/lib.rs` (`PINNED_CONVENTIONS`, `pinned_conventions`) |
| 2 Per-record verdicts | Every context, point, composition, count and relation gets its own `record valid` or `record INVALID (n problem(s), listed below)`. A physical or relation status is printed only for a valid record; an invalid record shows `not reported (record invalid)`. File verdict: `INVALID — k of n record(s) invalid; m problem(s)`. The exit code depends on record validity only | `points_check`, `points_report`, `rp_report` |
| 3 Species table and `rlt chem` | Elaborator `species-table` looks up the whole written string; it computes nothing from letters and elaborates no kernel term. `rlt chem WRITTEN CONVENTION` exits 0 when the formula is INTERPRETED, 1 when it is UNINTERPRETED ("neither true nor false") and 2 when the input is malformed or a pin mismatches | `conventions/chem-molformula.yaml`, `syntax/src/elab.rs`, `chem_report`, `cli/src/main.rs` |
| 4 Compositions and demonstration | Points can carry `element: {symbol, convention}` or `species: {written, convention}`. `compositions:` records which atoms a file counts as a molecule's, checked element by element against the entry. A `same-species` claim between points whose registered species differ is a registered-specification conflict | `records.rs` (`Composition`), `points_check`, `points/co2-and-o2.yaml`, `tests/accept/T7_one_plus_two.rlt` |

## 2. The species table

| Written | Species | Composition | Source and locator |
|---|---|---|---|
| `CO₂` | `carbon-dioxide` | C×1 O×2 | IUPAC-BRIEF-GUIDE-2015 §1, Table 3, row `CO2 \| carbon dioxide` |
| `O₂` | `dioxygen` | O×2 | IUPAC-BRIEF-GUIDE-2015 §1, Table 1, row `O2 \| dioxygen` |
| `COO`, `CO2`, `O2` | no entry: uninterpreted | — | — |

- **Citation.** IUPAC-BRIEF-GUIDE-2015 is registered with status `reference`: R. M. Hartshorn et al., *Brief guide to the nomenclature of inorganic chemistry*, Pure Appl. Chem. 87(9–10), 1039–1049 (2015), doi 10.1515/pac-2014-0718.
- **What was inspected.** Both table rows were read on 2026-11-08 at https://iupac.qmul.ac.uk/BriefGuide/inorganic.html, along with §1's statement that compositional names give no structural information. `COO` appears nowhere in the document.
- **Unresolved citations.** The Brief Guide has no table pairing element symbols with element names. So `C ↦ carbon` and `O ↦ oxygen` are RLT-authored labels, and the convention lists two unresolved items. The Red Book's IR-4.2.2 (molecular formulae, pp. 54–56) and Table I (p. 248) appear only in its contents list; they are uninspected and cited nowhere.

## 3. The demonstration (`rlt points points/co2-and-o2.yaml`, exit 0)

- **Basis.** "Keep the mathematical counts distinct from the records assigning atom identifiers to molecules." This is quoted from `RLT-002-T7-APPROVAL`, a new conversation source pinned in the registry. math5 is referenced by id only. Its defining excerpt is not quoted, because it is one indivisible unit and quoting it would copy math5's meaning.
- **Points.** `co2.molecule` (species `CO₂ ↦ carbon-dioxide`) and `o2.molecule` (`O₂ ↦ dioxygen`), each shown as "registered interpretation; specimen identity unestablished". Five atoms with elements C, O, O, O, O. All seven are `record valid · physical unestablished (evidence: 0)`.
- **Compositions.**
  - `comp.co2`: "C×1 O×2 matches CHEM-MOLFORMULA entry CO₂ (C×1 O×2)".
  - `comp.o2`: "O×2 matches … O₂ (O×2)".
  - Each carries the line "consistency with the registered interpretation; establishes no observation, bond or specimen identity".
- **Counts**, each `ACCEPT — unconditional theorem relative to registered axiom set PEANO-ADD, Γ = ∅`:
  - `count.co2`: 1 + 2 = 3, bound 1 ↦ {co2.c} · 2 ↦ {co2.o-1, co2.o-2}.
  - `count.o2`: 1 + 1 = 2.
  - `count.atoms`: 1 + 1 + 1 + 1 + 1 = 5, five distinct atoms.
- **Relations.** None. Structural, physical and identity relations stay unestablished.
- **Verdict.** `VALID — specification records consistent (13 record(s) valid; …)`.

## 5. Trust-boundary changes

| Item | After T7 |
|---|---|
| Kernel, `spec/`, `PINNED_AXIOM_SETS`, proof rules | unchanged |
| `PINNED_REGISTRY_SHA` | `5907956b…`, adding IUPAC-BRIEF-GUIDE-2015 (reference) and RLT-002-T7-APPROVAL (conversation) |
| `PINNED_STATUS_SHA` | unchanged |
| `PINNED_CONVENTIONS` | new: five conventions, each with an interpretation digest and an explanation digest |
| Elaborators | adds `species-table`, an untrusted, exact-string lookup whose output is printed in every report |

**New trusted assumptions.**
- The species and element tables are registered interpretations, reviewed through their pins.
- Element identifiers are RLT-authored labels until an IUPAC element table is inspected.
- A pin mismatch in any convention stops every command, including NAT-DEC proof checks, because all conventions load through one pinned loader.

## 6. What stays unestablished

- Whether any physical specimen is the species its record names.
- Every bond and structure claim.
- Every evidence item.

RLT reports these as `unestablished` or `evidence-submitted` and evaluates none of them.

## 7. Independent audit at 072eb82 and remediation

An independent agent audited the T7 layer adversarially on a clean clone. It found no blocking defect. Q1 (uninterpreted formulas), Q2 (convention integrity), Q5 (sources) and Q6 (regressions) held under every attempt; the two substantive defects were in Q3 (compositions and species).
- **Q1:** every Unicode, whitespace and look-alike variant of `CO₂` and `O₂` stayed uninterpreted.
- **Q2:** every pinned-field edit and YAML trick was caught or left the parsed content unchanged, and `canonical()` is unambiguous.
- **Q6:** a broken species table fails `verify.sh`.

Both substantive defects were reproduced independently, then fixed with regression tests:

| Finding | Severity | Counterexample at 072eb82 | Fix | Test |
|---|---|---|---|---|
| S1 same-species rule bypassed by adding a referent with no registered species | substantive | `between: [co2.molecule, o2.molecule, co2.c]`, evidence-submitted → VALID, exit 0 | Once any referent names a species, every referent must carry a registered species and all must agree; otherwise a registered-specification conflict listing each referent | `t7_audit_s1_same_species_cannot_be_diluted` |
| S2 two compositions with one id for one molecule (six atoms "match" CO₂) | substantive | second `comp.co2` on `co2.molecule` → VALID, 17 records | Record ids unique within a file (points, compositions, counts, relations share one namespace); at most one composition per molecule | `t7_audit_s2_unique_ids_and_one_composition_per_molecule` |
| M1 a composition checked records that were themselves inconsistent | minor | molecule with an element listed as its own atom still "matches" | A molecule in a composition names no element; an atom names no species | `t7_audit_m1_m2_composition_hardening` |
| M2 a duplicate atom was counted twice and reported as "in another composition", with a "matches" line on an invalid record | minor | `atoms: [co2.c, co2.o-1, co2.o-1]` | Duplicates counted once and reported as duplicates; the check line shows "matches" only for a valid record | same |
| M3 the free-text `class` field could imitate species text | minor | `class: "molecule · … species O₂ ↦ dioxygen …"` | `class` is a plain identifier | `t7_audit_m3_class_cannot_forge_species_text` |
| M4 a convention-pin failure was reported as a kernel rejection or a malformed proof | minor | prose edit → `lean` "not accepted by the RLT kernel", `rp` "proof file is malformed", `points` "0 of 0 record(s) invalid" | `lean` and `rp` print the actual verdict; `points` reports MALFORMED (exit 2) when no record could be read | `t7_audit_m4_pin_failures_are_named` |
| Q1 minor: U+034F, variation selectors, Hangul fillers, Braille blank printed invisibly | minor | `CO͏₂` printed like `CO₂` (still uninterpreted) | Added to the refused invisible set | `t7_audit_invisible_variants_are_refused` |
| Q2 minor: reordering a composition mapping changed printed order without a pin change | minor | `{O: 2, C: 1}` printed `O×2 C×1` | Compositions sorted by element symbol at load, so printed text follows the pinned content | `chem_co2` golden |

Test-harness change: `assert_points_invalid` accepts INVALID or MALFORMED, since a file whose pinned inputs cannot load is now reported as MALFORMED.

After remediation: 95 tests (golden 62, kernel 19, syntax 14); `verify.sh` exits 0 with "all checks hold"; `kernel/` and `spec/` are byte-identical to `origin/main`.

Limits recorded by the audit:
- RLT never checks a locator's text against its source.
- The species-source status check runs only in `validate`; other commands rely on the convention and registry pins.
- Any convention pin mismatch stops every command.
