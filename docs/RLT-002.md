# RLT-002 — First increment: implementation, tests and specification fidelity

**Approved scope.** Track A, the specification-record layer (RLT-002 Architecture and Test Review, approved with conditions on 2026-11-07). This increment is the smallest executable demonstration. It associates one checked equation with several distinct reading points and keeps their identities, conventions, assumptions and physical statuses.

**Result.** `points/oxygen-and-people.yaml` associates the kernel-checked equation `1 + 1 = 2` with two oxygen atoms and, separately, with two people. The report keeps four distinct identities, two particular scopes and four unestablished physical statuses. It records no relation among the reading points. 7 new tests (2 positive, 5 negative tests covering 20 refused variants) show that equal arithmetic establishes no structural or physical equivalence. `kernel/` and `spec/` are unchanged.

## 2. How a count is read

```
count.oxygen   "1 + 1 = 2" under NAT-DEC → ACCEPT — unconditional theorem relative to registered axiom set PEANO-ADD, Γ = ∅
  binding      1 ↦ {o2.atom-1} · 1 ↦ {o2.atom-2}
  identities   o2.atom-1, o2.atom-2 — 2 distinct reading point(s); class oxygen-atom
  scope        particular (the reading points listed)
  association  a specification record: the kernel checked the equation; this file states what each numeral counts
```

- **Kernel.** The equation, its Γ and its axiom set: the same outcome `rlt check` reports.
- **Specification record.** The binding of each numeral summand to a group of named reading points. `rlt validate` checks that it is consistent: one group per summand, each group the size of its numeral, distinct members, the right side equal to the number of distinct points, and every member particular. The record's author states the binding; the kernel proves only the equation.
- **Scope.** A count's conclusion keeps the scope of the reading points it binds, here `particular`. A count that states a wider scope is refused. Widening a scope needs its own source or evidence, and a count, a theorem or a shared class never supplies it.
- **Relations.** Sameness of structure or species, bonding and parentage are relation claims with their own status and evidence. When none is recorded, the report states that these relations stay unestablished. Two counts sharing one equation are reported as sharing it, and the sharing relates none of their reading points.

## 4. Specification fidelity

| Requirement | How it holds | Evidence |
|---|---|---|
| math0, math5, math29 stay source-controlled | A points file references a named reading point by id (`references: [math5]`). Its meanings stay only in `readingpoints/math5.yaml`, pinned and complete; a `meanings` field in a points file is refused | `t6_records_reference_without_duplicating`; `rlt validate` VALID with math5's 13 meanings unchanged |
| A context's basis is a verbatim source unit | `basis` must equal a whole unit of an excerpt of a registered available or conversation source | basis = "Preserve distinct reading points for two oxygen atoms and two human beings." [RLT-002-REQUEST]; a reworded basis is refused |
| Sources stay pinned | The two new conversation sources are part of the registry digest pinned in the binary | `rlt validate` VALID; the RLT-001 registry-pin tests pass |
| Numbers and physical referents | Each association is reported as a specification record, separate from the kernel verdict | the `association` line on every count |
| Scope retained | Particular points give a particular count; widening is refused | `t6_scope_is_retained` |
| Physical status separate | Each point carries its own status and evidence; every point here is `unestablished` with zero evidence; `supported` needs registered evidence | `t6_records_reference_without_duplicating` |
| Assumptions and conventions preserved | Counts bind to proofs by goal, convention, mode and Γ, using the audited RLT-001 binding | `t6_counts_are_bound_to_their_proof` |
| Unresolved conventions | `c = consent` and `C = +5 Constraint` stay unregistered and undefined | `sources/registry.yaml` |
