# RLT-003 · M3b — Robinson's Q, divisibility and ordering: implementation report

**Scope.** This report covers the M3b architecture as approved on 2026-11-08: decisions D1–D11 as recommended, plus two added test requirements.
- Substitution of axiom variables inside nested quantifiers.
- Folded and unfolded identity at the kernel boundary, with reports that separate the registered axiom set from the axioms a proof used.

M3b establishes meaning: axioms and definitions. It proves no non-divisibility result; that is M3c's work.

**Result.**
- ROBINSON-Q is registered: Q1–Q7, with the Open Logic Project's numbering and orientation. It is pinned, and Q4–Q7 are checked identical to PEANO-ARITH.
- Three definitions are registered and pinned: `<` (Q8's right-hand side), `∣` (Lean core's `Dvd Nat`) and `free235` (RLT-authored).
- The only kernel change is that `inst` instantiates axioms whose body is a formula. No inference rule is added; there are still 20.
- 15 accepted demonstrations and 23 rejected files behave as specified. 11 further cases run as Rust tests.
- Earlier verdicts are preserved. 273 of 274 earlier proof files give byte-identical reports. The 274th is M3a's R24, which tested that ROBINSON-Q was unregistered and is retargeted (§5).

### Trust-boundary and expansion arguments

- **T1, T2 (`inst` on formulas).** `subst_vars` replaces `Var` and nothing else. Bindings are checked well-sorted and locally closed by `check_sort(false)`, which refuses `Var` and bound indices, so a substituted term holds no index and needs no shift under the body's binders. The axiom body is locally closed under its own binders (`check_axiom_body`), so the result is locally closed (O1).
  - Soundness: an axiom is read as its universal closure, and any instance of a universally quantified formula holds in every model of the axiom.
  - Tests: B-R26 (a bound index offered as a binding is refused; nested-quantifier substitution is checked), B-R25 and B-A12.
- **T3 (axiom-file syntax).** Binders resolve to indices, free names must be declared variables, and a binder may not shadow an axiom variable (B-R27).
- **T4 (pins).** Tests: B-R1 (edited file), B-R2 (edited hash), B-R3 (substituted shared axiom), B-R5 (unregistered set), B-R6 (Q2 outside PEANO-ARITH).
- **T5, T6 (definitions, NAT-DEF).** NAT-DEF reads every NAT-LOGIC formula to the same kernel term (test `earlier_axiom_sets_and_conventions_are_unchanged`).
- **E1 (determinism).** One expansion per use. Arity is checked (B-R15). Size is bounded before building, and depth after (B-R22).
- **E2 (capture-freedom).** Parameters are the outermost indices of the body, and argument indices are shifted by the body's binder depth. Tested by `a_use_site_binder_is_never_captured` (∀z. z < 30 expands to ∀z. ∃z′. S(z′) + z = 30), B-R13, B-R14 and B-R29.
- **E3 (acyclicity).** A body sees only earlier definitions, so recursion and cycles are undefined names (B-R11, B-R12).
- **E4 (faithfulness).** The report's `checked goal` and `kernel form` are the formula the kernel checks. `folded` is the goal as written; `definitions` names every expanded definition with the file hash.
- **E5 (conservativity).** Expansion happens before the kernel and adds no assumption. Every accepted M3b theorem is a theorem of its expanded statement from ROBINSON-Q alone.

## 6. Report-format changes and deviations, for review

1. **The folded form is the written goal.** The architecture proposed three lines: written, folded kernel form, unfolded kernel form. The implementation prints:
   - `checked goal`: the unfolded formula, as the kernel checks it;
   - `kernel form`;
   - `folded`: the goal exactly as written;
   - `definitions`: the definitions expanded, with the file hash.

   A separate folded kernel rendering would need the elaborator to keep folded structure. The written goal carries the same information.
2. **No successor symbol in written goals.** NAT-DEF writes no S, so the goals of B-A4, B-A5, B-A8 and B-A12 use `x + 1`. Their proofs bridge x + 1 = S(x) with add_succ and add_zero. B-A8 is therefore ∀x. ¬(0 = x + 1), the source orientation, where the architecture named ∀x. ¬(S(x) = 0).
3. **M3a's R24 retargeted** (§5).
4. **`rlt lean` tactic list.** Lean is outside the trusted base.
   - `grind` and a case split are appended.
   - `simp` and `simp_all` must now close the goal (`(simp; done)`): a `simp` that made progress without closing a goal used to be taken by `first` and then failed compilation.
   - An `exists-intro` witness is offered from any step that proves the conclusion, not only the last.

   `lean/M3aGenerated.lean` is regenerated (17 tactic lines change; all 17 statements still compile with standard axioms). `lean/Generated.lean` and `M2Generated.lean` are unchanged, because equations keep `decide`.
5. **compare-reports covers tests/m3a**, which M3a's run excluded.

## 7. Limitations

- **Random testing** in a finite model does not apply to ROBINSON-Q. Q1 and Q2 force an infinite domain, so the soundness of the `inst` widening rests on the T1–T2 argument and its tests.
- **Lean's role.** Lean checks the statements and the tier-2 correspondence. It establishes no RLT derivation.
- **Free variables.** `∀x. x ∣ x` is stated but not provable in RLT: x = x × 1 needs induction, which is outside M3.
- **No backed-by links.** M3b adds no `backed by` link; the residue record refuses such keys (B-R18) until M3e.
