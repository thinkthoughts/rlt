# RLT-003 · M1 — Multiplication (closed examples): implementation report

**Scope.** The work follows "RLT-003 — M1 Architecture Approved with Corrections": decisions D1, D2, D4, D5, D7 and D8 approved, D3 resolved below, D6 and D9 deferred. Only M1 is implemented. M2, M3 and M4 are not.

**Result.** RLT proves the closed equations 2 × 3 = 6, 6 × 5 = 30 and 30 = 2 × 3 × 5, unconditionally, from the axiom set PEANO-ARITH. Each result establishes that one equation and nothing more general. In particular, none of them is a theorem about other moduli.

## 4. Incorrect axioms and generated derivations

- **Incorrect axiom.** Edit `mul_succ` to x × S(y) = x × y + S(x). Every PEANO-ARITH proof is then MALFORMED, because the file differs from its pin. It stays MALFORMED after `spec/axioms.yaml` is updated to the edited file's SHA-256, because the binary pin still refuses it. PEANO-ADD proofs are unaffected. Test: `m1_incorrect_axiom_cannot_bypass_the_pin`.
- **Tampered derivation.** Every single-numeral change to any step of the generated 30 = 2 × 3 × 5 proof is rejected (one check per step, 162 steps), and so is a proof with a step removed. Test: `m1_tampered_generated_steps_are_rejected`.
- **Generator.** It reproduces the committed proofs byte for byte, and writes no proof for 2 × 3 = 7, 30 = 2 × 3 × 4 or 0 = 1 × 1. Test: `m1_generator_reproduces_committed_proofs_and_refuses_false_equations`; `verify.sh` runs the same check.
- **Records.** A points record binding the conditional M1 proof as unconditional is INVALID. Test: `m1_records_keep_the_proofs_assumptions`.

## 5. Three kinds of support, kept apart

1. **Semantic soundness argument.** This is architecture review §3. With ℕ as the intended interpretation, the four axioms are true and each of the six rules preserves truth, now including `cong` over ×. This is the soundness case.
2. **Implementation evidence.**
   - 105 tests (golden 69, kernel 20, syntax 16), `scripts/verify.sh` and CI.
   - An independent adversarial audit.
   - These show that the code follows the rules. They are not a formal proof of kernel soundness.
3. **Lean comparison.**
   - `lean/Generated.lean` restates every accepted goal, e.g. `theorem M1_thirty : 30 = (2 * 3) * 5 := by decide`. Lean checks each statement independently, without seeing RLT's derivations.
   - Agreement is comparison evidence about these statements.
   - The GDT comparison file is not part of M1. Its proposed statements stay unverified until they compile against the pinned GDT source.

## 7. Reproduce

```bash
cargo build --release
target/release/rlt check tests/accept/M1_thirty.rlt
target/release/rlt gen "30 = 2 × 3 × 5" M1.thirty | cmp - tests/accept/M1_thirty.rlt
target/release/rlt lean tests/accept/*.rlt > lean/Generated.lean && (cd lean && lean Generated.lean)
scripts/verify.sh /path/to/source-repos
```
