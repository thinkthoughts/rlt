## 2. Work items and acceptance criteria

### P1 · F-009, DIC-difference uptake of a release (scientific quantity)

Questions: which quantity the two methods of `compute_cdr_metrics` are meant to estimate; whether the inventory method needs the release's own DIC removed; under which assumptions.

Method:
1. Read the stated intent: ROMS-Tools `docs/cdr_analysis.ipynb`, the Isometric air–sea gas exchange module cited there, ucla-roms `cdr_output.F90` comments.
2. Derive the interior DIC budget of `hDIC − hDIC_ALT_CO2` from the pinned sources (ucla-roms `step3d_t_mod.F90`, `cdr_output.F90`, `marbl_driver.F90`; MARBL surface flux and interior tendency), stating each term's sign, where it is accumulated, the integration domain, the initial condition and lateral transport.
3. Test against an oracle independent of the implementation: a closed-form one-box model of OAE, DOR and both, written out the way ucla-roms writes its output (window-averaged flux, instantaneous inventory), with analytic export and CaCO₃ terms.
4. Keep the change on its own branch, marked PROPOSED, unless the evidence settles the metric's meaning.

Accepted when: the identity is written out with sources; the oracle tests pass on the change and fail where the pinned code departs from the stated intent; each assumption and the alternative reading are recorded as open questions.

### P2 · F-008, units contract

Requirement: one explicit dimensional contract for every variable `compute_cdr_metrics` reads, based on UCLA-ROMS/MARBL conventions; refusal of every dimension that is not the contract's, with a message naming the variable and what it expected.

Accepted when: a parser reduces unit strings to a factor and dimension vector (amount N, equivalents E, length L, time T, mass M); `umol/kg` is refused as "not amount per area"; adversarial tests cover amount, mass, area, volume, time, mass-normalised, ambiguous and malformed strings; results in consistent units are unchanged; mixed prefixes give the same metrics as ucla-roms units.

### P3 · Regression evidence

Requirement: pinned-vs-patched suite results for C-Star (unit tests, chunked so that no run is killed for memory) and ROMS-Tools (full suite) with the composed branches; every pass/fail/skip/blocked outcome listed and explained.

Accepted when: logs exist for both trees with their commit hashes; every outcome that changes is accounted for; the ROMS-Tools branches merge without conflicts into one tree.

### P4 · Cross-repository compatibility

Requirement: check uneven partition and join against ucla-roms' own tools on NetCDF generated by ROMS-Tools; correct the partition guide; review the C-Star ↔ ROMS-Tools version dependency.

Accepted when: ucla-roms `Tools-Roms/partit` and `ncjoin` (tag 0.16.0) are built and run on a ROMS-Tools grid with uneven tilings, and ROMS-Tools' tiles and joins equal theirs; any difference is repaired with a regression test or recorded; every number in the revised guide is reproduced by a run.

### P5 · Further improvements

Numerical stability of the stretching function (F-011), measured against a high-precision reference and changed in ROMS-Tools and ucla-roms together; provenance and reproducibility of the evidence; efficiency where measurable. RLT's trusted kernel stays unchanged; RLT contributes certificates of concrete arithmetic facts and Lean proofs of general statements about the transcribed formulas.
