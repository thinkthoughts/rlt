## 2. Reporting contract, as implemented

| Exit | Meaning (printed on the report's `exit` line and as JSON `exit_meaning`) |
|---|---|
| 0 | record valid, its proof and specification pins current, and the RLT checker accepts the proof. It asserts nothing about semantic correspondence being complete or physical correspondence being established. |
| 1 | record valid; the checker rejects the proof (any stale pins are listed as well) |
| 2 | record invalid, or the checker reports the proof malformed |
| 3 | record valid, the checker accepts, but a proof or specification pin is stale |

- **Pins compared:** proof SHA-256 (of the bytes checked), convention, definitions SHA-256 (present exactly when the proof uses definitions), axiom-set id and SHA-256, checked goal, and Γ. Γ is compared pair by pair with the kernel theorem's assumptions, in name order.
- **Stale assessment vs stale record:** a semantic assessment is pinned to the goal it assessed and to its basis document's hash. When either differs, the semantic section reads `assessment stale` (JSON `semantic.assessment: "stale"`, with reasons), `record.state` stays `current`, and the exit is unchanged.
- **Source:** `registry_fidelity` (every excerpt equals a whole, normalised unit of the source's registered excerpts at the registry's commit) is reported separately from `upstream` (what checks the registry against the source itself: `scripts/check_excerpts.py` for pinned sources; "unpinned" for conversation records).
- **Physical:** `not-applicable` with a reason for purely mathematical statements; `relevant` reads status and evidence count from the named reading point's correspondence records.

**Trusted boundary.** The kernel block is produced by `check_inner`, the function `rlt check` runs, on exactly the bytes whose SHA-256 is printed; the JSON carries the full `rlt check` report (`kernel.check_report`). `rlt explain` is outside the trusted base: **a defect in this reporting layer could misstate a verdict to a reader or to a consumer of the JSON, although it cannot change what the kernel accepts.** The checked statement, Γ, axiom identities and proof hashes are printed in full so any reader can reproduce them with `rlt check`.

**JSON.** One `Explanation` value feeds both renderers. The writer escapes `"`, `\`, every character below U+0020, U+007F, U+2028 and U+2029, keeps object order fixed, and writes everything else as UTF-8.

## 4. Independent adversarial audit

The audit ran on a fresh clone at e860c05. On all 443 proof files, explain's kernel block and `kernel.check_report` agreed with `rlt check`, except the non-UTF-8 case (D1). Hashed bytes equal checked bytes. Stale pins gave exit 3, and assessments never moved the exit code. JSON stayed valid for every hostile record tried. Findings and disposition:

| Finding | Severity | Disposition |
|---|---|---|
| M1: Γ compared as printed text, so a single pinned formula containing `, g : …` matched two real assumptions; correct pairs in a different order read stale | major | Fixed: pairwise comparison with the kernel theorem's assumptions, both sides in name order; names must be identifiers and unique. Regression test with a two-assumption proof. |
| M2: U+2028 and bidi controls in a proof id or cited id could forge `verdict` lines in the text report | major | Fixed: every report value passes through one escaper covering control, separator, bidi and other invisible characters. Regression test. |
| M3: "Lean checks it" was claimed for any `.lean` file, including a theorem inside a comment | major | Fixed: references limited to top-level `lean/*.lean`; the report says "named in the file; scripts/verify.sh checks it with Lean #print axioms"; verify.sh compiles each referenced theorem and requires standard axioms only. |
| m1: blank assessor and impossible date accepted | minor | Fixed: non-blank assessor, real calendar date |
| m2: exit-1 text claimed current pins even when pins were stale | minor | Fixed: the exit text depends on the record state |
| m3: citations re-parsed from report text could be confused by parentheses in ids or paths | minor | Fixed: label, path and hash come from the parsed proof file |
| m4: excerpts normalised before comparison but displayed raw | minor | Fixed: an excerpt must be written as its normalised unit |
| D1: non-UTF-8 proof gave its own message instead of `rlt check`'s | minor | Fixed: such files go through `rlt check`'s own read path; regression test |
| Absolute paths in loader messages | observation | Fixed: problems are shown repository-relative |
| A missing basis, Lean file or reading point makes the record invalid (exit 2) | observation | Kept by design: references must resolve. A *changed* basis is an assessment matter (exit 0). |
| `assessed_by` is free text and could name the kernel | observation | Kept: attribution is a claim printed as the record's claim, beside a fixed scope line that kernel acceptance never sets it. |
| Small race between path check and read; non-breaking spaces pass the string check | observation | Recorded; the bytes read are the bytes hashed and checked. |

**Re-audit 1 (18c5cb2).** M1, M2, m1–m4 and D1 fixed. Partly fixed: M3 (verify.sh found Lean references with a regex, so block-style or quoted references escaped the gate) and absolute paths (trailing-slash roots). **New major:** the D1 fix re-read a non-UTF-8 file through `rlt check`'s path, so a file swapped between the two reads could be reported ACCEPT against the hash of other bytes (reproduced once in 354 runs). Fixed at bf8a422: `check_bytes_outcome` builds `rlt check`'s report from the bytes already read; verify.sh takes Lean references from `rlt explain --format json`; root spellings normalised.

**Re-audit 2 (bf8a422).**
- The race is closed: in 5,873 swap runs, every verdict matched the bytes hashed, and none gave exit 0.
- The Lean gate catches a block-style, quoted reference to a theorem that exists only in a comment.
- Root spellings `DIR/`, `DIR//` and `.` are fixed.
- **New minor:** with a relative root such as `a`, the root text was removed inside other path names (`data/../x.rlt` was shown as `dat../x.rlt`). Fixed in the final commit: the root is removed only where it starts a path (`relative_problem`, with a unit test of six spellings).

## 5. Deviations and notes

- **Usage text.** `rlt` without arguments now lists `explain`. All other existing output is byte-identical.
- **Additive code outside the new module:** `check_preread_outcome` (6 lines, calls `check_inner` unchanged), and `load_statement` with its helpers in `records.rs`. Existing loaders are unchanged.
- **Schema refinements beyond the review:**
  - assumption names must be identifiers and unique, and are compared in name order;
  - `assessed_by` must be non-blank and `date` a calendar date;
  - excerpts must be written as their normalised unit;
  - Lean references are limited to `lean/*.lean`.
