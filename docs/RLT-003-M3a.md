# RLT-003 · M3a — Logical infrastructure: implementation report

**Scope.** This report covers the M3a specification as approved on 2026-11-08: Q-a to Q-f as proposed, plus two clarifications.
- The substitution motive is defined precisely.
- exists-elim has an explicit soundness argument under Q-f.

M3a adds formulas, parameters and 14 logical rules to RLT's kernel. It proves nothing about divisibility or residues; M3b and the modulo-30 classification are separate milestones.

**Success criterion (approved).** "M3a accepts correctly derived first-order statements, rejects invalid applications of inference rules, and preserves every earlier proof judgment and reading-point interpretation."

**Result.**
- All 17 accepted files (A1–A16, with A12 in two files) are unconditional theorems.
- All 42 rejected and malformed files (R1–R41, some split across files) are refused with the required exit code and reason; R26, R28 and the O8 size limit run as Rust tests.
- Every earlier proof judgment is unchanged. Of 215 earlier proof files, 213 give byte-identical reports. In the other two, one message now lists 20 registered rules instead of 6. Every reading-point, points, residues, chemistry, written-layer and Lean report is byte-identical; `rlt validate` adds the NAT-LOGIC convention (§6 lists all three exceptions).

**Local assumptions.** `(hyp h)` keeps its meaning for a declared h. An undeclared h is a local assumption only when some imp-intro, or-cases or exists-elim in the same file names h; otherwise the step is refused exactly as before ("assumption `h` is undeclared in the goal"). So every earlier file, none of which discharges anything, behaves as before. Within one file each local name is bound to one formula (R30), and local names may not reuse declared names (R15, R31).

## 2. Soundness argument (O1–O9)

**Semantics.**
- A structure M interprets 0, S, + and × over a domain. M ⊨ A when M satisfies the universal closure of every axiom in the set A.
- An assignment σ gives each parameter a value.
- Γ ⊢ φ is **sound** when, for every M ⊨ A (A the theorem's axioms) and every σ: if M, σ ⊨ ψ for each ψ in Γ, then M, σ ⊨ φ.
- Every formula a theorem holds is locally closed (O1), so σ fixes its truth value.

**Lemmas** (each by induction on φ; terms contain no binders):
- **L1 (open).** For t locally closed: M, σ ⊨ open(φ, t) iff M, σ[x ↦ ⟦t⟧σ] ⊨ φ, reading φ's outermost index as x.
- **L2 (close).** M, σ ⊨ ∀x. close(φ, a) iff M, σ[a ↦ v] ⊨ φ for every v. The same holds with ∃ and "some v".
- **L3 (freshness).** If a ∉ params(ψ), then M, σ ⊨ ψ iff M, σ[a ↦ v] ⊨ ψ, for every v.

**O2, per rule.** Assume M ⊨ A and Γ (the conclusion's context) holds at σ.

| Rule | Why the conclusion holds |
|---|---|
| refl, symm, trans, cong | = is interpreted as identity in M: reflexive, symmetric, transitive, preserved by S, + and ×. |
| inst | The axiom holds for all values of its variables; the instance takes the values ⟦tᵢ⟧σ. Parameters in tᵢ are evaluated by σ. |
| hyp | φ is in Γ. |
| subst | ⟦s⟧σ = ⟦t⟧σ. By L1, open(ψ̂, s) and open(ψ̂, t) both evaluate ψ̂ with x ↦ that same value, so they agree. |
| and-intro, and-left, and-right, or-left, or-right, imp-elim | Truth tables. |
| false-elim | ⊥ holds in no M under no σ, so the premise's Γ cannot hold. |
| imp-intro | Γ = Γ(sA) ∖ {h}. If φ holds, then every formula of Γ(sA) holds, because the kernel checked that h, if present, states exactly φ. So ψ holds. |
| or-cases | φ ∨ ψ holds. If φ holds: Γ(sB) ∖ {h1} holds and h1 states φ (checked), so χ holds. The ψ case is symmetric, with h2 removed from sC only. An h1 used in sC is not removed (R16). |
| forall-intro | a ∉ params(Γ). For any v, by L3, Γ holds at σ[a ↦ v], so φ holds there. By L2, ∀x. close(φ, a) holds at σ. |
| forall-elim | By L1, with the value ⟦t⟧σ. |
| exists-intro | sA proves open(φ, t). By L1, φ holds with x ↦ ⟦t⟧σ, so ∃x. φ holds. |
| exists-elim | See the argument below. |

**exists-elim under Q-f.** Rule: from Γ₁ ⊢ ∃x. φ and Γ₂ ⊢ χ, conclude Γ₁ ∪ (Γ₂ ∖ {h}) ⊢ χ. The kernel checks that h (if present) states open(φ, a), and that a is absent from φ, from χ and from Γ₂ ∖ {h}. Γ₁ passes through whole.

1. Γ₁ holds at σ, so ∃x. φ holds; pick a value w with φ true at x ↦ w.
2. Let σ′ = σ[a ↦ w]. a ∉ φ, so open(φ, a) holds at σ′ (L1, L3); h holds at σ′.
3. a ∉ Γ₂ ∖ {h}, so those formulas still hold at σ′ (L3). So Γ₂ holds at σ′, and χ holds at σ′.
4. a ∉ χ, so χ holds at σ (L3).

Γ₁ is used only at σ, before a is reassigned, so it may mention a. Tests:
- A13: Γ₁ mentions a; accepted.
- R32: the branch also uses that assumption; refused.
- Kernel test `exists_elim_q_f_keeps_the_premise_gamma_and_discharges_only_h`: Γ₁ is kept, only h is removed from the branch, and a w that also appears in Γ₁ survives.

**Final checks.** The goal and declared assumptions contain no parameters, so their truth does not depend on σ. An unconditional theorem has Γ = ∅, so its goal holds in every M ⊨ A.

## 6. Deviations from the approved specification (approved 2026-11-08)

1. **NAT-LOGIC instead of extending NAT-DEC (Q-e). Approved.** NAT-DEC's explanation is printed inside `rlt points` reports, so adding the logical readings to NAT-DEC would have changed earlier specification reports.
   - NAT-DEC stays byte-identical, with the same pins, and so do the reading-point specifications that print it.
   - Written formulas use a separate pinned convention, NAT-LOGIC (origin rlt-authored). It reads every NAT-DEC equation to the same kernel term and adds the seven logical symbols.
2. **Accurate rule list in the unknown-rule message. Approved.** The message lists all 20 registered rules. These are the explicit regression exceptions to byte-identity, and the only ones:

   | Earlier report | Old line | New line |
   |---|---|---|
   | `tests/m1/R3a_comm_rule.rlt` | … rule comm is unregistered (registered: refl, symm, trans, cong, inst, hyp) | the same, listing the 20 rules |

   In each case the verdict, step and exit code are unchanged.
3. **Local assumptions recognised by their discharges. Approved after a scope check (§6a).**
4. **Test counts.** R12, R22 and R23 each have two files, and R23b is an exit-1 REJECT. R26 and R28 run as Rust tests, because they need a scratch repository or a very large file.

## 6a. Scope check for deviation 3

The pre-scan decides only which names `(hyp h)` may introduce without a declaration. It never removes an assumption from any theorem. Removal happens in the kernel, at the discharging step, and only from the premise that step names:
- imp-intro removes h from its one premise;
- or-cases removes h1 from sB only and h2 from sC only;
- exists-elim removes h from sB only, and the existential premise's Γ passes through whole.

The final check then refuses any undeclared assumption left in the final theorem's Γ. So a discharge elsewhere in the file, reachable or not, cannot remove an assumption from the final theorem's dependencies. Identity is the name plus its formula: one formula per local name in a file, checked at every `hyp` and every discharge (R30, R35).

| Case | Test | Result |
|---|---|---|
| h used by the final theorem; the only discharge of h is in a step outside the final theorem's dependency tree | R38 | refused: local assumption h remains in Γ |
| h introduced in one branch and discharged in another branch; the branches are combined | R39 | refused, same reason |
| exists-elim discharges w from its branch while the existential premise's Γ also holds w | R40 | refused: w stays in Γ through the major premise |
| h discharged, then introduced again and used | R41 | refused |
| the same h introduced and discharged separately in two branches | A16 | accepted, Γ = ∅ |
| a vacuous discharge naming h for a second formula | R35 | refused |
| or-cases where one case uses the other case's name | R16 | refused |
| the same, in conditional mode | R14 | refused, never reported as conditional |

The refusal message now reads "it is undeclared, and no discharge removed it from this theorem's dependencies". This is accurate when a discharge exists elsewhere in the file.

## 8. Independent adversarial audit (at 6ba9f1e) and follow-ups

An auditor who did not write the code worked on a fresh clone at 6ba9f1e.
- Its baseline: `cargo test` and `verify.sh` all pass, and compare-reports against bf3c9cc shows exactly the three documented differences (§3).
- PEANO-ADD, PEANO-ARITH and the reading points are unchanged (`git diff bf3c9cc -- spec readingpoints sources residues …` is empty).
- Verdict: **merge yes; no findings** (no soundness break, no materially false claim).
- Unsound derivations attempted: 43 hand-written attack files covering eigenvariable escapes, discharge confusion, capture and alpha-equality, the written-goal elaborator, and resource limits. All were refused or sound.
- Random testing, as supporting evidence:
  - about 590,000 written-formula parses;
  - 642,191 random kernel derivations over all 20 rules, each theorem evaluated in ℤ/3 (a three-element model of PEANO-ADD and PEANO-ARITH) under all 27 parameter assignments. No counterexample.
- This testing is supporting evidence only. A finite model can miss an unsound rule whose counterexamples need ℕ. The soundness of the rules rests on the written arguments O1–O9 (§2), which the audit checked against the code.
